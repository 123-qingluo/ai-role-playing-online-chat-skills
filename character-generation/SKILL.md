# 人物设定生成（CBVTM · 纯线上 chatbot）

> 一句话原型进，一份可以直接交给扮演方的人物设定出。
> 集合原型，非指所有个体。不用于临床诊断、真实个体标签化、决定论预测。

**这个 skill 只管「写设定」，不管「演」。** 演由角色扮演方按设定执行，或交给 `chat-evolution`。

## 何时用

- 用户要「一个角色」「人物设定」「给个 NPC」「这个人怎么设定」
- 已有人物雏形，要把它写成能演的版本
- 要产出可以交给下游扮演的人物
- 原型只有一两个词、读不出身份或渠道时，愿意先对齐几个关键点

## 何时不用

| 想要什么 | 去哪 |
| --- | --- |
| 只要一张快速卡、不要可演细节 | `character-design-mini` |
| 要深推四层视角、跨层约束、行为逻辑 | `character-design-max` |
| 已经在扮演，要维持人物不走味 | `chat-evolution` |
| 要剧情、要对话脚本 | 都不是本 skill。本 skill 不写剧情 |

## 产物：三条硬线，缺一条就是废稿

1. **可发** —— 每条性格都要落成**他能发出去的字**：一句话、一次沉默、一个表情。不能停在形容词，也不能靠动作。
2. **可拒** —— 三档拒绝各一句原话；特殊拒绝对特定对象确实不适用时，标「不适用」并说明，其余两档仍须原话。
3. **可停** —— 写明「不做什么、不知道什么、不主动说什么」，否则 AI 会退化成万能客服。

## 生成流程（0 + 4 步，按序）

### 第 0 步 要不要先问（触发式）

**默认不问，直接出 14 栏。** 只有输入读不出「身份」或「渠道」时，才先对齐，问完再出。

| 输入 | 读得出身份 + 渠道？ | 走哪条 |
| --- | --- | --- |
| 「夜班店长，冷」 | ✓ 店长 / 顾客群 | 直接生成 |
| 「殡仪馆化妆师」 | ✓ | 直接生成 |
| 「傲娇青春少女」 | ✗ 两者都缺 | 先问 |
| 「一个很酷的人」 | ✗ | 先问 |

**只问缺的那几项，不把四步重问一遍。** 通常两问就够：

| # | 问什么 | 什么时候问 | 主要影响 |
| --- | --- | --- | --- |
| 1 | 三个聊天渠道 + 三类关系 | 渠道或关系读不出 | 栏 2、12 |
| 2 | 根冲突（只留一对） | 冲突推不出，或用户给了多对 | 栏 1、3、5、6、7—9 |
| 3 | 三档拒绝的第一句原话 | 想贴用户的语气时（可选） | 栏 7—9 |
| 4 | 三个「绝不」 | 想贴用户的边界时（可选） | 栏 10、11、14 |

每问附一句「我猜：……」，用户可回「按推荐」或逐条改。

第 1、2 问对应的正是第一步与第二步——**能自己推就自己推**。问只是为了贴用户的预期，不是流程必需。

**对齐纪律**

- 用户说「直接生成」→ 立刻出，不再问。
- 只答一半 → 答的用答的，没答的用推荐补齐并标「假设：……」，不得写成用户确认。
- 用户转话题 → 不强行生成。
- 给了多对冲突 → 追问一次「哪一对是根冲突」；仍不答，按第一对生成并标假设，其余不入这一版。
- 不问 `style`；数值永远从正文推，没把握就省略。

### 第一步 抽原型

从一句话里抽出三样：**身份**（干什么的）、**渠道**（他在哪个群、跟谁私聊）、**关系网**（常跟谁打交道）。
三样齐了才能往下。缺哪样先看第 0 步答案；仍缺再假设，并显式写出「假设：……」。

一句话原型也能生成，但不能跳过这一步——「冷面店长」这三个字里，藏着的正是这三样。

### 第二步 立一对冲突

**只立一对，不要三对。** 优先用第 0 步的根冲突答案；没答就按推荐或假设。冲突是「两个他都想要、但不能同时要」的东西，写成「A vs B」。

- 冷面店长：**规矩 vs 人情**
- 话痨外卖员：**想被看见 vs 怕被记住**
- 阴郁高三生：**想被救 vs 不肯开口**

一对冲突能生成全部行为；三对冲突只会生成一堆标签。

### 第三步 冲突翻译成行为（最容易跳过，也最致命）

**每条性格都必须落到下面四类可观察物之一**：

| 落到哪 | 例（冷面店长） |
| --- | --- |
| 说话方式 | 句子短、不用语气词、反问代替回答 |
| 发送方式 | 一句话拆三条 / 一次说完整段 / 只发一个句号 |
| 拒绝方式 | 三档各一句原话 |
| 沉默方式 | 被问私事时只回「哦」，或者不回 |

**落不到这四类里的描述，删掉。也要删掉一切他做不到的**——撤回、已读、语音、隔三小时才回：那要靠客户端，模型只能假装。

「她外冷内热」是废句；「她骂完人，会补一句『明天记得带伞』」才是设定。

### 第四步 装边界

写清三样：**不会做什么**（行为底线）、**不知道什么**（防万能）、**不主动说什么**（防自来熟）。

## 十四栏模板（缺一栏不可交付）

| # | 字段 | 写什么 | 反例 |
| --- | --- | --- | --- |
| 1 | 一句话定位 | 他是谁、靠什么活、卡在哪 | 「一个复杂的男人」 |
| 2 | 身份与渠道 | 具体职业 + **他出现在哪三个聊天场合**（如班级群、游戏好友、论坛私信） | 「上班族」 |
| 3 | 说话方式 | 句长、语气、标点习惯、口头禅 ×2 | 「说话很有趣」 |
| 4 | 语码切换 | 对客人 / 对熟人 / 对上级，分别什么口气 | 「对谁都一样」 |
| 5 | 文字习惯 | **只能写他打出来的东西**：标点、表情、拆条还是整段、说错话怎么补 | 「很有魅力」 |
| 6 | 情绪三态 | 生气 / 高兴 / 难过，**各是什么发送行为**（**不写形容词**） | 「情绪丰富」 |
| 7 | 拒绝·软 | 一句原话 | 「会委婉拒绝」 |
| 8 | 拒绝·硬 | 一句原话 | 「有时会强硬」 |
| 9 | 拒绝·特殊 | 对特定的某个人，一句原话 | — |
| 10 | 边界 | 不会做的三件事 | — |
| 11 | 无知区 | 不知道的三件事 | 空着（= 万能，废稿） |
| 12 | 关系网 | 三个人，各一句态度 + **在哪个渠道联系** | 「人缘不错」 |
| 13 | 第一条消息 | 他主动发的第一句（纯文字，不带动作） | — |
| 14 | 禁用词 | 这角色绝不会说的三个词 / 句式 | — |

第 11 栏和第 14 栏最容易被忽略，也最有用：**无知区防万能，禁用词防走味。**

完整字段说明与填充示例：`references/template.md`

## 纯线上五条硬约束（写进设定，不是写给执行方）

设定里要显式交代下面五条，否则扮演方会按「通用助手」的习惯去演：

| # | 约束 | 在设定里怎么写 |
| --- | --- | --- |
| 1 | 一条消息一个施为力 | 「他一次只做一件事：要么拒绝，要么应下，不会又拒又劝」 |
| 2 | 长度倾向 | 「话少：一般不超过 25 字，急了更短」（话少 / 中 / 多，选一档） |
| 3 | 只发自己 | 「他不描述自己在哪、在做什么，也不写对方看到消息的反应；只有他发出去的字」 |
| 4 | 被问是不是 AI | 「他会反问回去，不当真解释」——写清具体反应，别留空 |
| 5 | 冷场怎么办 | 「对方不回，他也不追问；最多过很久发一个句号，或者发个表情」 |

这五条是设定的**行为条款**，不是技术说明。

## 可选输出：下游契约块

设定正文写完后，**可选**在末尾附一个 ```` ```cbvtm ```` 围栏块（YAML），供 `chat-evolution` 读取。

- 给：下游能精确复现你的三档拒绝与风格常量
- 不给：下游也能跑，全部走默认值（这是契约保证的）
- 四问答案只填已有字段（如 `channel` / `relations` / `refusals` / `boundaries` / `ignorance` / `banned_words`）；根冲突留在正文，不新增字段，不改契约版本
- 特殊拒绝标「不适用」时，契约省略 `refusals.special`；不要为了填字段虚构一个对象

字段与写法见 `references/contract.md`。**契约块不能替代正文**——正文是给人读的，块是给机器读的，缺正文就是废稿。

## 交付前质检

逐条过，任何一条不过就返工。完整判据见 `references/quality-gate.md`。

| # | 检查项 | 不合格的样子 |
| --- | --- | --- |
| 1 | 每条性格都有对应行为 | 出现「内心」「其实」「本质上」 |
| 2 | 三档拒绝都有原话（特殊不适用可标「不适用」并说明） | 只写「会拒绝」；或标了「不适用」却没说为什么 |
| 3 | 无知区非空 | 全空，或写「几乎什么都知道」 |
| 4 | 边界非空 | 没写不会做什么 = 什么都肯做 |
| 5 | 冲突只有一对 | 列了四五对矛盾 |
| 6 | 能应对跑题 | 只覆盖预设场景，用户一跑题就无话可说 |
| 7 | 没有表演痕迹 | 写「他要表现得冷漠」或「他靠在门框上」——那是舞台提示，不是聊天账号 |
| 8 | 四问落地 | 四问确认过或推荐补齐的根冲突、拒绝原话、边界 / 无知区 / 禁用词没有进入正文，或被模型改掉 |
| 9 | 假设透明 | 跳过四问或用推荐补齐，却没在开头写「假设：……」 |

## 按需加载

本文件常驻。下面四件只在对应时刻读，**不要一次全读**：

- `references/template.md` —— 写 14 栏时逐栏对照
- `references/quality-gate.md` —— 交付前跑一遍
- `references/examples.md` —— 第一次生成、或不确定某种写法时参照
- `references/contract.md` —— 要输出契约块时读；与 `chat-evolution` 侧内容逐字一致

## 输出格式

1. 先写假设（若有）
2. 14 栏正文，按编号顺序
3. 可选：`cbvtm` 契约块
4. 不给解释、不给剧情、不给对话示例——除非用户要

四问答案直接落入 14 栏；不另给 brief、四行锁定或问答记录。只有走第 0 步并用推荐补齐，或完全自行推定时，才在开头写「假设：……」并列出未确认项。
