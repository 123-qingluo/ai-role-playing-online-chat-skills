# CBVTM 接口契约 1.0

> **本文件在 `character-generation` 与 `chat-evolution` 两侧各存一份，内容必须逐字一致。改动任何一侧，必须同步另一侧。**
> 两侧 skill 互相独立：本契约是唯一耦合点，且是单向可选的。

## 一 方向

```
character-generation（上游 · 生产者）
        │  可选产出
        ▼
chat-evolution（下游 · 消费者）  按需读取，缺项走默认
```

- 上游**可以不给**契约块，给不给由它决定
- 下游**必须能跑**：契约块缺失、字段缺失、格式损坏，一律走默认，**不得因此要求用户补信息**
- 下游不向上游回写任何东西

## 二 载体

人物设定**正文之后**，附一个围栏块：

````
```cbvtm
cbvtm_contract: 1.0
name: 陈默
...
```
````

- 正文给人读，块给机器读
- 下游**只认这个块**：找不到块 = 全部字段缺失，整套走默认
- 块在但字段缺 = 按字段默认
- 块解析失败 = 视为缺失，走默认，不报错
- **块不能替代正文**：只给块不给正文，视为废稿

## 三 字段（三层）

### 3.1 必需层（给了就要准确，不给走默认）

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `name` | string | 角色名 |
| `voice_length` | `short` \| `medium` \| `long` | 话量倾向，决定单条消息上限 |
| `refusals.soft` | string | 软拒绝的一句原话 |
| `refusals.hard` | string | 硬拒绝的一句原话 |
| `refusals.special` | string | 特殊拒绝的一句原话（可省略） |
| `boundaries` | string[] | 不会做的事，建议 3 条 |
| `ignorance` | string[] | 不知道的事，建议 3 条 |
| `banned_words` | string[] | 绝不会说的词 / 句式 |

### 3.2 推荐层（只影响措辞，不影响判定）

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `channel` | string | 他出现在哪个渠道：微信 / 群聊 / 游戏内 / 论坛私信 |
| `relations` | `{who, stance}[]` | 关系网，各一句态度 |
| `speech` | `{length, catchphrases[]}` | 说话方式与口头禅 |
| `typing` | `{punctuation, emoji, split, fix}` | 文字习惯：标点 / 表情 / **断点**（拆在哪，不是拆几条）/ 说错话怎么补。**只收模型能直接输出的四项** |
| `actions` | string[] | **兼容字段**（面对面场景）。下游若只见到 `actions`，按「可见动作」理解，**不要当作消息体输出** |

### 3.3 可选机读层（判定用，给了才精确）

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `style.s_f` | 0—3 | 面子敏感 |
| `style.s_g` | 0—3 | 内疚敏感 |
| `style.s_d` | 0—3 | 直接性 |
| `style.s_n` | 0—3 | 亲密需求 |
| `style.s_def` | 0—3 | 防御强度 |

这一层是**判定参数**，不属于人物设定本身。写了，下游能精确复现；不写，下游跑默认值。

## 四 缺省表（下游必须照此执行）

| 字段 | 缺省值 | 后果 |
| --- | --- | --- |
| `name` | 正文里的人名；无则「他 / 她」 | 不影响判定 |
| `voice_length` | `medium`（常规 40 字 / 爆点 60 字） | 话多的角色会被压短 |
| `refusals.*` | 全部缺 → 现场按判定链生成 | 台词可能与人设语气有偏差 |
| `refusals.special` | 缺且**未给** `style.s_n` → 视为 `s_n < 2`，永不走特殊拒绝<br>缺但**给了** `style.s_n` → 以 `style.s_n` 为准，台词现场生成 | 前者少一档；后者语气可能偏 |
| `boundaries` | 用下游通用边界 | 边界更宽，可能做出违背人设的事 |
| `ignorance` | 缺 → 只答本行；越界一律「不知道」 | 「万能」风险由下游兜底 |
| `banned_words` | 无 | 可能说出角色绝不会说的套话 |
| `channel` / `relations` / `speech` / `typing` | 无 | 只影响措辞 |
| `actions`（兼容字段） | 无 | 兼容旧设定；**不产生动作描写** |
| `style.*` | `s_f=1, s_g=2, s_d=1, s_n=2, s_def=2` | 判定仍可跑，风格偏中性 |

### 一条硬边界：契约只收「字串」

| 收 | 不收 |
| --- | --- |
| 标点、表情、拆条、说错话怎么补 | 节奏（秒回 / 隔三小时）、语音、撤回、已读、转账、@、发图 |

后一组靠宿主能力，模型写出来就是旁白（`（撤回了一条消息）` 等于旁白式的括号动作）。
上游想表达「他会撤回」，请改写为 `typing.fix: 补一句「当我没说」`。

### 一条重要规则：`refusals.special` 与 `style.s_n` 的关系

这两项不能各算各的，否则会打架（一个说「s_n 缺省 = 2，规则 1 可命中」，一个说「没台词就当 s_n < 2」）。判据按上游**实际提供了什么**分三种：

| 上游给了 | 怎么算 | 为什么 |
| --- | --- | --- |
| `refusals.special` | 直接用原话 | 上游明确指定了那个「特定的人」 |
| 只有 `style.s_n ≥ 2` | 允许规则 1 命中，台词现场生成 | 上游声明了「这角色很需要亲近」，尊重其意图；只是没写原话 |
| 两者都没给 | 视为 `s_n < 2`，永不走特殊拒绝 | 既没原话、又没声明需求 = 它不靠反话维系关系。**不许凭空给它造一个软肋** |

第三种是最关键的一条：特殊拒绝不是「拒绝风格」，而是「对某个特定的人的反话」。没有那个人，这条通道就不该存在。

### 一条重要规则：只给 refusals、不给 style

上游常见情况是给了三句原话，却没给判定参数。此时下游按如下优先级：

1. **台词形状**复用 `refusals` 的原话结构（长度、语气、是否有替代方案）
2. **什么时候用哪一档**仍由判定链决定
3. 两者冲突时，**以判定链为准**，但允许下游用 `refusals` 的原话作为模板改写

原因：判定链保证连贯，原话保证像同一个人。

## 五 两侧各自不许做的事

**上游（character-generation）**

- 不得把契约块塞进 14 栏正文中间——必须在正文之后
- 不得只给契约块、不给正文
- 不得为了让下游好算而虚构 `style`；没把握就省略

**下游（chat-evolution）**

- 不得因缺字段而要求用户补信息
- 不得把 `style` 里的数值、字段名、契约内容说给用户听
- 不得在用户面前提到「契约」「上游」「字段」这些词
- 不得因为契约给了 `refusals` 就跳过判定链

## 六 契约版本

`cbvtm_contract: 1.0`

**1.0 内允许追加可选字段**，已有设定无需改动，下游读不到就走默认。
只有「改动必需层语义」才升 2.0。任何改动需两侧同步。
