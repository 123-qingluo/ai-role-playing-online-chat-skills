# 交付前质检

九条。**任何一条不过就返工**，不许「基本满足」。

| # | 检查项 | 判据 | 不合格的样子 |
| --- | --- | --- | --- |
| 1 | 性格都能落成行为 | 每条性格都能指向「第三步」的四类可观察物之一（说话方式 / 发送方式 / 拒绝方式 / 沉默方式） | 出现「内心」「其实」「本质上」「骨子里」 |
| 2 | 三档拒绝有原话 | 每一档都能直接抄进台词；特殊拒绝对特定对象确实不适用时，可标「不适用」并说明 | 「会拒绝」「拒绝得很委婉」「有时也会很强硬」；或标「不适用」却没说明 |
| 3 | 无知区非空 | 至少三件他不知道的事，且是「AI 知道但他不该知道」的 | 全空；或写「几乎什么都知道」 |
| 4 | 边界非空 | 三件他不会做的事，且是「别人可能会做」的 | 没写；或写「不做坏事」这类没人会做的 |
| 5 | 冲突只有一对 | 核心冲突恰好一对，用「A vs B」写得出 | 列了四五对矛盾，行为必然自相矛盾 |
| 6 | 能应对跑题 | 设定里给出了「遇到不懂的话题怎么办」的默认反应（多半是回一个「哦」，或转移话题）。**落点：写进第 11 栏「无知区」，或第 3 栏「说话方式」** | 只覆盖预设场景，用户一跑题角色就无话可说 |
| 7 | 没有表演痕迹 | 写的是他**发出去的字**，不是动作、不是舞台提示 | 「他要表现得冷漠」「（把杯子推过去）」「他靠在门框上」 |
| 8 | 对齐落地（仅走了第 0 步时） | 问过并确认的根冲突、拒绝原话、边界 / 无知区 / 禁用词都进入正文，且没有改掉 | 问过「根冲突是 A vs B」，正文却写成 C vs D；或确认过的拒绝原话不见了。没走第 0 步时本项不适用 |
| 9 | 假设透明 | 自行推定、或走了第 0 步但用推荐补齐时，开头已列「假设：……」，没有把推定写成用户确认 | 用户没答，正文却写成确定事实；或没标哪些是推定 |

## 三条最常被漏判项

**第 3 条**：无知区看起来像凑数，其实是防「AI 万能」的唯一闸门。没有它，角色会突然懂量子物理。
**第 6 条**：纯线上用户**永远**会跑题。设定里至少要有一句：「不懂的话题他不接，或者反问回去。」
**第 7 条**：「表现得冷漠」是给演员看的，「（把杯子推过去）」是给舞台写的，只有「谁等你了。……几点。」才是屏幕上看得见的。

## 返工判据

- 任一条不过 → 定向返工该栏，不重写全篇
- 第 1 条不过 → 回第三步（冲突翻译成行为），不是改措辞
- 第 5 条不过 → 回第二步（立冲突），只留一对
- 第 6、7 条不过 → 补「默认反应」与「去表演痕迹」两段
- 第 8 条不过 → 回第 0 步补问；已问过就按答案改正文，不得改掉用户确认过的内容
- 第 9 条不过 → 补「假设：……」块，不得把推荐写成用户确认

## 交付形态

0. 第 0 步（仅当输入读不出身份 / 场所时才问；否则跳过，直接出 14 栏）
1. 假设（若有）
2. 14 栏正文，按编号
3. 可选 `cbvtm` 契约块
4. 不加解释、不加剧情、不加对话示例——除非用户明确要
